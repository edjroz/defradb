Range-based set reconciliation vs default sync

The case in one line: to discover a tiny difference inside a large set, the default sync must communicate the whole set (O(n) control bytes), while negentropy narrows in on just the difference (O(d·log n)) — a 188× control-traffic reduction at n=100k for a 2-item difference, at the cost of a few extra logarithmic round-trips.

Negentropy numbers are measured directly from the Phase-2 engine (internal/db/p2p/negentropy); the default-sync baseline is modelled as a naive full-identifier exchange at the same per-item accounting — a generous lower bound on what the real DAG-walk costs. See tests/bench/reconcile/README.md for methodology.

Charts 1–4 are the modelled synthetic sweep (the asymptotic case). Charts 5–6 are measured on real nodes for Phase 3/M1: at per-document scale reconciliation costs more control traffic than broadcast doc-sync (one session per document), with identical payload. Charts 7–8 show M2's per-collection batching collapsing that per-document overhead back to ~broadcast levels. Charts 9 & 12 are the payoff, measured on real nodes across both axes of O(diff·log n) vs O(n). Chart 9 fixes the diff at one doc and grows the collection 50→1000: default control climbs linearly (2.1KB→42KB, ~42 B/doc) while reconciliation stays nearly flat (2.7KB→6.4KB, log n) — a 6.5× gap at 1000 docs. Chart 12 fixes the collection at 500 docs and grows the difference: default is flat at 21KB (it lists every docID regardless), while reconciliation rises with the diff (5.3KB→14.9KB from 1 to 250 changed docs). Reconciliation still wins at half the collection changed (250/500); the crossover where a large diff makes it lose is beyond that — the measured analogue of the modelled chart 3. Chart 10 is the cost side: the always-on ordered-index write adds only a small per-commit overhead. Chart 11 takes it off the in-process bench and onto real Docker containers on one host bridge (2, 5, 10 benchnodes in a star; node0 diverges one doc in a 50-doc collection). As the network grows, reconciliation's total control bytes scale ~linearly with the star's edges while default broadcast grows super-linearly, so the reduction compounds: 1.8× at 2 nodes, 3.7× at 5, 14× at 10 (90KB vs 1.28MB). Every run converged with identical document state on all nodes. Charts 13 & 14 isolate the long-differing-branch case: a 10-doc two-sided fork with branches 3 vs 50 commits deep. The control cost is unchanged by depth (chart 13) — a deep branch is still a single differing head — while only the payload (blocks fetched + merged) scales with depth (chart 14). Reconciliation pays nothing extra to discover a deep divergence. See tests/bench/reconcile/README.md and tests/bench/crossdevice/.
